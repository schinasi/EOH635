Data Codebook

Reference for variables in class_data_raw.csv

This page documents every variable in class_data_raw.csv. Variable names, types, and one-line descriptions come from the course’s official codebook.xlsx (also available in data_raw/); background and methodology for the tract-level environmental measures is pulled in from Classdata_arealevelmeasures_description.docx. It’s meant as a reference to check back to while working through the lessons — you don’t need to read it top to bottom.

TipAbout this dataset

The primary class dataset is based on the Southeast Pennsylvania Household Survey and represents a simulated cross-sectional survey of adults living in Philadelphia in 2015 (participants identified via random-digit dialing in the scenario the data represent). It’s fictitious data designed to resemble real-world data, not actual study participants — this lets you work through realistic epidemiologic problems without using identifiable data.

class_data_raw.csv contains 2,000 observations and 38 variables: health outcomes, health behaviors, demographic/socioeconomic characteristics, perceptions of neighborhood conditions, and geographic location. PHL_NDVI_summer_annual.csv (384 Philadelphia census tracts) is a separate file you’ll link in during Lesson 1.

Area-Level (Tract-Level) Variables

These variables describe the census tract (geoid10) each participant lives in, rather than the participant individually — everyone living in the same tract shares the same value.

Population Density

Variable Type Description
popden_km Numeric Population density in the census tract (people per km²)

Traffic Volume

Variable: ctb1traff (Numeric — “Traffic density” per the official codebook)

Measured and estimated traffic volumes for major roads by road section are available annually from PennDOT (2005–present). Air pollution levels from traffic typically return to background levels within 100 to 300 m of roads. We calculated kernel densities of average daily traffic from PennDOT traffic data within 100 m and 300 m of road centerlines, on a 30 m grid, for southeastern Pennsylvania.

  • 100 m was chosen based on work done for the New York City Community Air Survey.
  • 300 m was chosen to account for the road width of wider roads.

The variable in the data set represents the average of the 100 m kernel-density average daily traffic in the participant’s residential census tract. Higher value = greater traffic volume.

Data sources

  • Background: Annual Average Daily Traffic by road segment, from the Pennsylvania Department of Transportation (PennDOT), Bureau of Planning and Research, Geographic Information Division.
  • Data obtained: Downloaded from www.pasda.psu.edu (2005–2015 downloaded 11/4/2016; 2016–2017 downloaded 4/26/2017).

Land Cover: Tree Canopy & Grass/Shrub Cover

Variable Type Description
hrlctree Numeric Tree canopy cover (proportion in the census tract)
hrlcgrass_shrub Numeric Grass or shrub cover (proportion in the census tract)

Derived from the Philadelphia Land Cover Raster, which provides data on surface types in Philadelphia in 2008 and an update in 2018 (the 2015 value in this data set was created using linear interpolation between the two). The data identifies seven categories: tree canopy, grass/shrub, bare earth, water, buildings, roads, and other paved surfaces. When tree canopy covers another surface type, that area is placed in the tree canopy category. Data were gathered with the assistance of the University of Vermont Spatial Analysis Laboratory.

You can calculate a total vegetation measure by summing hrlctree and hrlcgrass_shrub together.

Data sources

  • Background: The American Community Survey (ACS), administered by the U.S. Census Bureau, is a nationwide survey providing social, economic, housing, and demographic data. The Census Bureau combines five consecutive years to produce estimates at the census tract level.
  • Data obtained: ACS 5-year average data for 2017–2021, downloaded from the U.S. Census Bureau. Race/ethnicity variables were calculated as the percentage of persons in the census tract identifying with each category, across all age/gender groups. Data may be missing if a measure was suppressed by the Census Bureau due to low sample size (to protect against potentially identifying information).

Crime Variables

Variable Type Description
ctviolra Numeric Violent crime rate — units unconfirmed, see flag below
ctviolkm Numeric Violent crime rate per km² in the census tract

Police-reported crime data is available from OpenDataPhilly. Yearly crime rates and densities (per square mile/km) for the City of Philadelphia were created for calendar years 2006–2016. Crimes are categorized, with rates/densities available for violent crime, narcotic drug violations, and property crime, summarized by 2010 U.S. Census Tract. These rates were generated to provide objective measures of neighborhood safety, and can be used to explore the influence of crime and safety on health outcomes and behaviors.

Warning⚠️ Unresolved: units for ctviolra

Two source documents disagree on the unit for ctviolra, and this hasn’t been confirmed yet:

  • Classdata_arealevelmeasures_description.docx describes it as a rate per 10,000 population.
  • The official codebook.xlsx (and the create_data.R script that generated it) describes it as “Total violent crime incidents per 1,000 residents.”

Leaving this unresolved for now, per instructor note — don’t state a specific unit for ctviolra in student-facing material until this is confirmed.

Note

The source .docx also lists a missing-data sentinel value of 9999999999 for the crime variables. That value does not actually appear anywhere in class_data_raw.csv (checked directly) — it looks like a leftover description from the original real-data source system, not something present in this simulated class dataset. No special recoding is needed for ctviolra/ctviolkm on that account.

Known Data Quirks

  • age has 4 implausible outliers coded as 116 years old. These are intentional (built into the simulated data for teaching purposes) — an example of the kind of value that should catch your eye during exploratory data analysis (e.g., via summary() or a histogram), well before any modeling. You’ll work through recoding this in the Exploratory Data Analysis lesson.
