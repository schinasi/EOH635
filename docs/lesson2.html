Why Explore Data Before Analyzing It?

It’s tempting to skip straight to the “real” analysis — but exploratory data analysis (EDA) isn’t a formality before the real work starts. It is part of the real work. Before you can trust any regression result later in the course, you need to know your data cold: what each variable looks like, where the errors are, and what a “normal” value even is for each one.

This class dataset is a simulated example of something very real in environmental epidemiology: data assembled from multiple sources, each with its own error patterns. Here, individual-level answers came from a household survey, and neighborhood-level measures (tree canopy, traffic, poverty, crime) were linked in by census tract — the same kind of linkage you did yourself in Lesson 1. Every data-collection method has its own way of introducing error:

  • Surveys / interviewer-administered questionnaires — recall bias, misunderstood questions, data entry mistakes.
  • Monitors and administrative/electronic data — instrument drift, missing readings, records that were never meant for research use.
  • Linked data (like the tract-level variables here) — mismatched geographic identifiers, or a value that’s technically correct but describes the neighborhood, not the person.

Broadly, the errors EDA is designed to catch fall into three buckets:

  1. Missing data
  2. Logical inconsistencies — combinations of values that can’t both be true
  3. Outliers — values so extreme they’re more likely to be errors than reality

We’ll work through each of these in turn.

Note

One more framing note before we start: everything in this lesson is descriptive, not inferential. We’re not running hypothesis tests or p-values here — we’re looking at distributions to understand the data and catch problems before any modeling starts. That distinction matters enough that it’s worth stating explicitly: descriptive analysis characterizes what’s in front of you; inferential analysis (coming later in the course) is what lets you draw conclusions and test hypotheses from it.

Checking for Logical Inconsistencies

Missing data is easy to spot — R shows you NA directly. Logical inconsistencies are sneakier: every individual value can look perfectly plausible on its own, but two variables together can’t both be true. A classic example from environmental health survey data: someone recorded as biological sex “male” who also reports an age at first menstruation. Neither value looks wrong in isolation — the problem only shows up when you look at both at once.

The tool for catching this is one you already know: table(), applied to two variables instead of one, to see every combination that actually occurs in the data.

Note💡 Why as.character()? — click to reveal

high_blood_pressure is stored as an integer 0/1 flag, not a category. Without as.character(), ggplot treats it as a continuous numeric axis and tries to draw a single boxplot (or a strange, mostly-empty range of “groups” between 0 and 1) rather than two separate boxes for “0” and “1”. Wrapping it in as.character() (or factor()) tells ggplot to treat it as a categorical variable, so it draws one box per group as intended. This is the same integer-flags-that-are-really-categories issue you first ran into with str(data) back in Lesson 1.

Question to consider: Based on what you see here, what is the relationship between high blood pressure and % tree canopy cover?

Note

Remember this is a crude estimate of the relationship — and, per Week 1, an association (however real it looks here) is not the same thing as causation. Even if this boxplot shows a clear pattern, several other explanations besides “tree canopy directly affects blood pressure” are still on the table, including confounding by some third variable related to both. We’ll return to formal tools for evaluating that (regression models, and later in the course, confounding assessment with causal diagrams) — for now, just describe what you see.

🚀 Quick-Start Script for Your Own Project

======================================================

Everything above walked through each step one at a time, with the browser-only fetching code mixed in. Below is a single reusable script — this is what you’d paste into a new .R or .qmd file inside EOH635_project/scripts/, running on your own computer with class_data_processed.csv already sitting in data_processed/ (from Lesson 1). Swap in your own variable names wherever you see # <- CHANGE THIS, and use it as a starting checklist for Milestone 1.

Tip💻 In your RStudio script 
# ---- Setup ----
library(tidyverse)

# ---- Read in your data ----
data <- read.csv(file.path("data_processed", "class_data_processed.csv"))

# ---- 1. Missing data: check every column at once ----
colSums(is.na(data))

# ---- 2. Logical inconsistencies: cross-tabulate variables that should agree ----
# Example template -- replace both variables with a pair relevant to your own project
table(cut(data$age, breaks = c(-Inf, 21, Inf), labels = c("Under 22", "22 and over")),
      data$education)

# ---- 3. Outliers + summary statistics ----
summary(data)                                    # all variables
summary(data %>% select(where(is.double)))       # numeric variables only

# ---- 4. Frequency tables for categorical variables ----
table(data$education)                            # <- CHANGE THIS to your own categorical variables
prop.table(table(data$education)) * 100

# Every non-numeric variable at once:
non_numeric_data <- data %>% select(-where(is.double), -id, -year)
lapply(non_numeric_data, function(x) {
  if (is.factor(x) || is.character(x) || is.logical(x) || is.integer(x)) {
    counts <- table(x, useNA = "ifany")
    percentages <- prop.table(counts) * 100
    cbind(Count = counts, Percentage = percentages)
  } else {
    NULL
  }
})

# ---- 5. Recode an implausible value once you've found one ----
# Template, following the age > 105 example above:
data$r_age <- ifelse(data$age > 105, NA, data$age)   # <- CHANGE THIS to your own variable/cutoff

# ---- 6. Visualize a single continuous variable ----
ggplot(data, aes(x = age)) +                                    # <- CHANGE THIS to your exposure or outcome
  geom_histogram(binwidth = 5, fill = "blue", color = "black") +
  labs(title = "Distribution of Age", x = "Age", y = "Frequency")

# ---- 7. Visualize your exposure-outcome relationship ----
# If your outcome is a 0/1 flag, wrap it in as.character() so ggplot treats it as a category:
ggplot(data, aes(x = as.character(high_blood_pressure), y = hrlctree)) +  # <- CHANGE THIS
  geom_boxplot(fill = "orange") +
  labs(title = "Tree canopy cover by high blood pressure status",
       x = "High blood pressure", y = "Tree canopy cover")

# If both your exposure and outcome are continuous, use a scatter plot instead:
ggplot(data, aes(x = pov_allage, y = hrlctree)) +                # <- CHANGE THIS
  geom_point(color = "purple") +
  labs(title = "% living in poverty vs. tree canopy cover",
       x = "% living in poverty", y = "% tree canopy")

# ---- 8. Check a candidate confounder against your exposure ----
ggplot(data, aes(x = education, y = hrlctree)) +                 # <- CHANGE THIS
  geom_boxplot(fill = "orange") +
  labs(title = "Tree canopy cover by education", x = "Education", y = "Tree canopy cover")

# ---- 9. Grouped summary table ----
data %>%
  group_by(education) %>%                                       # <- CHANGE THIS
  summarize(
    avg = mean(hrlctree, na.rm = TRUE),                          # <- CHANGE THIS
    median = median(hrlctree, na.rm = TRUE),
    max = max(hrlctree, na.rm = TRUE),
    min = min(hrlctree, na.rm = TRUE)
  )
