How this works, piece by piece:

  • We can also look at the proportion and percentage of participants in each category.

Putting this together: the first line, table(), gives raw counts — 1,066 participants coded "< Bachelor's" and 934 coded "Bachelor's degree or higher". prop.table() takes that same table and converts it to proportions of the total (each cell divided by 2,000), and multiplying by 100 turns those proportions into percentages: about 53.3% of participants have less than a bachelor’s degree, and about 46.7% have a bachelor’s degree or higher. All three lines describe the exact same underlying counts — they’re just three different units (counts, proportions, percentages) for reporting the same distribution, and which one you’d report depends on your audience (a raw count is often more useful in a table you’re building for yourself; a percentage usually reads more naturally in written text).

It’s important to understand how to manipulate the variables in your data frame. Consider, again, the education variable.

  • What type of variable is education? Let’s use str() to check how it’s coded in our data frame.

Based on this, we see that education is a character variable — we know that because str() labels it chr right at the start of the output.

str() uses a short abbreviation for every variable type, and it’s worth being able to recognize the common ones at a glance:

Abbreviation Type Example
chr character (text/string) education, gender
int integer (whole numbers) id, year
num numeric (double — can hold decimals) age, hrlctree
logi logical (TRUE/FALSE) rare in survey data, but common after a comparison like age > 65
Factor factor (categorical, with defined levels) not currently used in this dataset — R reads categories in as chr by default, but some analyses expect Factor instead

Creating a numeric version of the education variable

Right now, education is a character variable — useful for reading and for table(), but not for most quantitative work. Regression models, correlations, and most statistical functions in R need numeric input — they can’t compute something like a mean, a correlation coefficient, or a regression slope on the text strings "< Bachelor's" and "Bachelor's degree or higher". To use education status as a predictor or outcome in that kind of analysis later in the course, we first need a consistently coded numeric (here, binary 0/1) version. Let’s do this now, using base R’s ifelse():

Note

A note for later in the course: if you only ever plan to use education as an explanatory variable (a predictor) in a regression model — not as the outcome — converting it to a numeric 0/1 variable isn’t your only option. R’s regression functions (like lm() and glm()) can also take a factor variable directly as a predictor, and will automatically create the 0/1 coding behind the scenes (this is called “dummy coding”). For a variable with just two categories like this one, numeric 0/1 and factor give you the same result either way. The numeric approach shown here is worth learning first because it makes that dummy-coding step explicit rather than hidden — but once you’re comfortable with what’s happening, factor() is often the more natural choice for a categorical predictor, especially one with more than two levels.

What happened here? This line creates a new variable called num_education, a numeric version of education, using ifelse():

  • The code checks each value of education.
  • If the value is "< Bachelor's" (less than a bachelor’s degree), num_education is set to 0.
  • For all other values (presumably at least a bachelor’s degree), num_education is set to 1.

So this line recodes a categorical education variable into a binary (0/1) numeric variable, where:

  • 0 = less than a bachelor’s degree
  • 1 = bachelor’s degree or higher

Note: in R there are lots of ways to do the same thing. Another way to recode this variable is with the dplyr package (loaded as part of tidyverse) instead of base R’s ifelse().

Quick reminder of the syntax before you try it: mutate() adds (or changes) a column in a data frame, and if_else() works like ifelse() — a condition, then the value to use when it’s TRUE, then the value to use when it’s FALSE. Put together, the general pattern looks like:

data <- data %>%
  mutate(new_column_name = if_else(some_condition, value_if_true, value_if_false))

📝 8. Merging Data with External Information

======================================================

A lot of times in environmental epidemiology, we have additional environmental information that we want to link into our data. Examples include:

  • Air pollution data
  • Housing data
  • Tract-level sociodemographic composition variables
  • Green space data
  • Crime data

You can probably think of additional types of data we might want to link in.

Why would we want to do this? Here’s a concrete example: if we’re interested in studying the association between residential air pollution exposure and asthma diagnosis, our survey data alone won’t have an air pollution measurement for each participant — so we’d want to link in a separate data source that does have it, matched to where each participant lives.

We can do this by merging a second data frame — which has the environmental information of interest — into our primary data frame, by combining them using a common variable or variables.

  • Often, we use information about participants’ neighborhoods (e.g., census tracts) to merge in environmental data. A census tract is a small, relatively permanent geographic area defined by the U.S. Census Bureau — roughly neighborhood-sized, typically a few thousand residents — that’s commonly used in public health research as a proxy for someone’s local environment, since exact addresses usually aren’t available (or shared) for privacy reasons.

Let’s do that now.

Load another dataset

You’ll find an additional data frame, which contains neighborhood-level (tract-level) data on NDVI (greenness), called PHL_NDVI_summer_annual.csv. (For the other tract-level environmental and sociodemographic variables already in data — like hrlctree or pov_allage — see the Data Codebook.)

This data frame shows the median value of the summertime NDVI value for each census tract in Philadelphia — that is, how green each census tract is. NDVI stands for Normalized Difference Vegetation Index. NDVI ranges in value from -1 to 1.

  • Negative values represent water.
  • Values close to 1 mean dense vegetation.
  • Values close to 0 mean a lack of vegetation (there might instead be lots of concrete).

Write code to check this — for example, group data2 by geoid10 and count the number of distinct X2015_NDVI values within each tract. Why should that be true? X2015_NDVI is a tract-level measurement — it describes the neighborhood, not the individual person. 📂 9. Saving Your Processed Data

======================================================

Currently, our new data frame just lives in our R environment (or, on this page, in your browser’s temporary in-browser R session). Once we close R (or this browser tab), we lose our changes unless we save them. We can either rerun this code again, or save our new data frame with any changes we made. Let’s do this now.

Note: it’s good practice to save your data frame using a new name, and — per this course’s project convention — into data_processed/, not data_raw/. That way data_raw/class_data_raw.csv stays untouched as your original source, and anyone (including you, later) can tell at a glance that data_processed/ files were generated by a script rather than hand-edited.

Why does that separation matter so much? Think about reproducibility (recall this from Week 1): the whole point of the data_raw/ → script → data_processed/ pattern is that your script, not a person clicking around in a spreadsheet, is the record of every transformation applied to the data. If class_data_raw.csv ever got hand-edited directly, there would be no way to tell what changed or why — the original data would effectively be lost, and nobody (including future you) could regenerate it from scratch. Keeping data_raw/ untouched means you can always delete data_processed/ entirely and rebuild it by just re-running your script — which is exactly what “reproducible” means in practice.

Tip💻 In your RStudio script

Below is everything put together as a single clean script — this is what actually goes in your .R or .qmd file inside EOH635_project/scripts/, running on your own computer with class_data_raw.csv and PHL_NDVI_summer_annual.csv already sitting in data_raw/.

Tip💻 In your RStudio script

Copy the whole block below into a new script in RStudio to get started on your own computer. There’s no downloading step here — R just reads the files straight from your data_raw/ folder.

# ---- Setup ----
library(tidyverse)

# ---- Read in your data ----
data <- read.csv(file.path("data_raw", "class_data_raw.csv"))
PHL_NDVI_summer_annual <- read.csv(file.path("data_raw", "PHL_NDVI_summer_annual.csv"))

# ---- Take a first look ----
head(data)
str(data)
dim(data)
summary(data)

# ---- Recode education into a numeric 0/1 variable ----
data <- data %>%
  mutate(num_education = if_else(education == "< Bachelor's", 0, 1))

# ---- Match variable types before merging ----
data$geoid10 <- as.character(data$geoid10)
PHL_NDVI_summer_annual$GEOID10 <- as.character(PHL_NDVI_summer_annual$GEOID10)

# ---- Merge in the NDVI (greenness) data ----
data2 <- merge(data, PHL_NDVI_summer_annual,
                by.x = "geoid10", by.y = "GEOID10", all.x = TRUE)

# ---- Check that the merge worked ----
dim(data2)
head(data2)

# ---- Save your processed dataset ----
write.csv(data2, file.path("data_processed", "class_data_processed.csv"), row.names = FALSE)
